- **documented**: Three-phase language learning. For an experienced programmer learning another language, start with small puzzles and consult documentation as unfamiliar syntax, input, strings, and errors arise. Next, build a WebSocket chat server to encounter modules, libraries, and concurrency. Finally, build something large enough for design and maintenance choices to become consequential. Compare the same project across familiar and unfamiliar languages to isolate differences. Use this when evaluating a language, not as a universal beginner curriculum. There is no pass score: move on when the current phase no longer exposes the questions you need answered. He cautions that the roadmap may transfer poorly to a radically different paradigm. - **inferred**: Prediction, experiment, and explanation, unnamed. While reading documentation, first predict what a construct means, run a small example, and compare the result with the explanation. - **inferred**: Choose the learning route by prior experience, unnamed. A beginner should build very simple things with visible feedback and gradually increase complexity. Someone who already programs can build first and later read a book against concrete mistakes. These are alternative routes, not a contradiction: choose based on existing concepts and the risk of importing old-language assumptions. Do not treat a short course or reference reading as evidence of mastery. - **inferred**: Profile before pooling, unnamed. First inspect CPU samples for substantial application hotspots; a flame graph's horizontal position is not a timeline. Then inspect allocation separately, because a function with modest CPU share can still create many short-lived objects. - **documented**: Represent and measure before compressing, unnamed. Estimate the raw data budget from dimensions, representation, rate, and audience; record a fixed-workload baseline. Remove information that the receiver can reconstruct, explicitly account for any quality lost through quantization, and only then test compression. In his frame-streaming project he compared run-length encoding, XOR between adjacent frames, and Huffman coding; short runs could cost more, and the decoder also needed the encoded bit length. These are project-specific transformations. Choose them when the data has the assumed repetition and when quality, implementation, and interoperability costs are acceptable. - **inferred**: Regression search: logs or bisect, unnamed. If the failing file is known, changes are infrequent, and messages are informative, inspect file-scoped patches and search likely terms first.
