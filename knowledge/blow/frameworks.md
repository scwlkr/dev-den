- **inferred**: Unnamed — total-cost design review. Start with the actual job and list the alternatives. For each, examine runtime cost, implementation and debugging effort, restrictions on callers, failure modes, and effects on future changes. A safety mechanism can prevent bugs yet increase completion time if its constraints are costly to work around. Do not count prevented bugs or workaround costs as zero without evidence. Use this when comparing language mechanisms or engine architectures; there is no numerical acceptance threshold in the sources. - **documented**: 85% solution — common cases without universal machinery. Identify the frequent cases, give them a straightforward mechanism, and make unsupported cases explicit instead of accumulating exceptions inside one abstraction. The percentage is a heuristic, not a measured coverage target. Prefer this when exceptional requirements would complicate every ordinary use; reconsider if excluded cases dominate the real workload or force users into worse workarounds. Small specialized libraries can coexist with broader variants until experience identifies a useful default. - **documented**: Unnamed — remove redundant responsibilities. Enumerate representations of a relationship and the code that keeps them synchronized. - **documented**: Unnamed — allocator context and temporary storage. Carry an allocator in a standard context so downstream code can substitute allocation behavior without editing every call. For values known to die before a reset boundary, allocate from a temporary arena and reset it in bulk, such as once per frame. Audit all consumers for retained references before adopting the convention. This reduces individual allocation and cleanup work, but external APIs may allocate invisibly and independently compiled DLL boundaries can complicate context propagation. - **documented**: Unnamed — choose numerical representations by invariants. Specify maximum acceptable error, values that must survive exactly, and the input distribution before selecting an encoding. Center reconstruction reduces truncation bias under the stated random-input assumptions but cannot represent zero, which can make a stationary object creep. Endpoint rounding preserves zero and one at a resolution cost. Nonuniform intervals may improve common cases, but concentrating precision can worsen maximum error. Pick according to the application rather than mean error alone. - **documented**: Unnamed — select interpolation by required properties. Separate the path of a rotation from its speed along that path. Compare constant velocity, commutativity, and minimal torque against the actual use: iterative inverse kinematics may need only monotonic progress, while multi-pose blending benefits from order-independent combination. - **documented**: Unnamed — change the unit of reasoning for LOD seams. Rather than enumerate combinations of neighboring octree blocks, reason about triangles and their referenced chunks: one triangle has only three vertices and can touch at most three chunks. Record seam vertices by chunk and vertex index, rewrite references as chunks are reduced, and treat runtime selection as a query that can later be indexed. Bound allowed LOD differences if full storage is too expensive. This is a representation change, not a guarantee of zero preprocessing cost. - **documented**: Unnamed — practical mipmap filtering. Treat downsampling as a signal-processing problem, choose a CPU budget and filter width, and compare frequency response with actual images. Generate each level from the original image when quality warrants avoiding accumulated distortion. For gamma-encoded color, convert to linear light before filtering and encode afterward.
