# David Heinemeier Hansson (DHH): positions

Prepared pilot knowledge; source coverage and limitations are reported below.

- **documented**: Rails should equip generalists to build integrated systems. DHH personally favors including server-rendered views, while supporting API use as a compatible secondary mission. ([dhh-461d2e74ffac9a](https://rubyonrails.org/doctrine) / evidence dhh-461d2e74ffac9a-89da59d3e94f; [dhh-461d2e74ffac9a](https://rubyonrails.org/doctrine) / evidence dhh-461d2e74ffac9a-5473ef1e7034)

- **documented**: Active Record’s combination of persistence and domain logic is a practical trade-off for database-backed web applications. He nevertheless accepts different paradigms in different layers, including occasional presenters in views. ([dhh-461d2e74ffac9a](https://rubyonrails.org/doctrine) / evidence dhh-461d2e74ffac9a-27fd483e876e; [dhh-461d2e74ffac9a](https://rubyonrails.org/doctrine) / evidence dhh-461d2e74ffac9a-f19299e8e398)

- **documented**: In his 2004 language comparisons, he preferred Ruby for reusable MVC web frameworks but acknowledged that PHP could support maintainable object-oriented code and was useful for small dynamic tasks. He described his preference over Python as subjective. ([dhh-f67ffa285b5dc9](https://signalvnoise.com/archives/000606) / evidence dhh-f67ffa285b5dc9-3a88cac5262b; [dhh-f67ffa285b5dc9](https://signalvnoise.com/archives/000606) / evidence dhh-f67ffa285b5dc9-4d1fa074fbfa)

- **documented**: He sees separation through MVC or similar patterns as increasingly valuable with application complexity, while considering combined concerns acceptable for a small guestbook. ([dhh-f67ffa285b5dc9](https://signalvnoise.com/archives/000606) / evidence dhh-f67ffa285b5dc9-ab1c5c9636dc)

- **documented**: Rails 7’s no-Node frontend default uses browser modules, HTTP/2 and import maps; applications that need bundlers can still choose one through loose integration. This is a default choice, not a rejection of JavaScript. ([dhh-223d94218730eb](https://rubyonrails.org/2021/12/15/Rails-7-fulfilling-a-vision) / evidence dhh-223d94218730eb-d96af5e5759d; [dhh-223d94218730eb](https://rubyonrails.org/2021/12/15/Rails-7-fulfilling-a-vision) / evidence dhh-223d94218730eb-86240d0a4f5f)

- **documented**: He assesses server-rendered HTML with Turbo and Stimulus as capable of rich interfaces with less frontend complexity than many JSON-centered approaches, without claiming identical behavior in every application. ([dhh-dac6015dd2ae7f](https://world.hey.com/dhh/five-big-open-source-gifts-from-us-c1b42c1b) / evidence dhh-dac6015dd2ae7f-791503b6b9c6; [dhh-223d94218730eb](https://rubyonrails.org/2021/12/15/Rails-7-fulfilling-a-vision) / evidence dhh-223d94218730eb-f7015b89c418)

- **documented**: For Basecamp and HEY, he reports that SSD-backed fragment caching held more data at lower cost than their prior Redis setup. Solid Queue uses database features for transactional guarantees and observability; SQLite support has lower throughput than supported databases with SKIP LOCKED. - **documented**: He favors a lower deployment learning curve for smaller applications while acknowledging the sophistication and standardization of Kubernetes-oriented tooling. ([dhh-dac6015dd2ae7f](https://world.hey.com/dhh/five-big-open-source-gifts-from-us-c1b42c1b) / evidence dhh-dac6015dd2ae7f-40e5bfce79b6)

- **documented**: He recommends calibrating code review to experience, change size and risk: a newcomer should receive review, while a small, low-criticality change by someone deeply familiar with the code may not need it.
