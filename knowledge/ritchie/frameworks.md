# Dennis M. Ritchie: frameworks

Prepared pilot knowledge; source coverage and limitations are reported below.

- **documented**: Analyze portability at multiple layers: language and hardware, operating-system interfaces, and transferred data formats. Ritchie and Johnson found that moving the OS itself could avoid some target-interface obstacles, but did not remove machine-specific porting work. - **documented**: A language implies a machine model: compare that model with target hardware before expecting either easy implementation or efficient execution. Ritchie and Johnson identified character-pointer representation and calling conventions as consequential examples. ([ritchie-be88b7b72521cb](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/portpap.html) / evidence ritchie-be88b7b72521cb-eaa7cb323f6f; [ritchie-be88b7b72521cb](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/portpap.html) / evidence ritchie-be88b7b72521cb-f94692f59206; [ritchie-5d25d1308143eb](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/clcs.html) / evidence ritchie-5d25d1308143eb-591410add537)

- **documented**: C declarators were built by analogy with expressions used to access objects: indexing, calling, and indirection correspond to composed types. Ritchie valued the unifying idea while acknowledging difficult nested syntax. ([ritchie-91fa14fdc827e6](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/chist.html) / evidence ritchie-91fa14fdc827e6-7cc95771d1b3; [ritchie-91fa14fdc827e6](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/chist.html) / evidence ritchie-91fa14fdc827e6-afda41a8616a)

- **documented**: Ritchie and Thompson described device files and standard descriptors as a way to reuse naming, protection, and ordinary I/O. The shell handles redirection so individual commands need not implement it. ([ritchie-4495b38593615b](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/cacm.html) / evidence ritchie-4495b38593615b-1d7ab0b69aef; [ritchie-4495b38593615b](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/cacm.html) / evidence ritchie-4495b38593615b-39f880ab09d2)

- **documented**: Unix pipes reused ordinary file I/O and commands. In the system Ritchie and Thompson described, however, a common ancestor had to establish a pipe; Ritchie later also identified linear pipeline notation as limiting multiple-stream arrangements. ([ritchie-4495b38593615b](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/cacm.html) / evidence ritchie-4495b38593615b-25f71f8cb269; [ritchie-7ca8eec9ac8af9](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/hist.html) / evidence ritchie-7ca8eec9ac8af9-d728fd6527c4; [ritchie-7ca8eec9ac8af9](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/hist.html) / evidence ritchie-7ca8eec9ac8af9-0c8d8f666b4d)

- **documented**: For stream I/O, Ritchie described modules communicating chiefly with neighbors through messages. Block references reduce copying and per-character overhead, but modules must handle unpredictable block boundaries. ([ritchie-5cfbec4274be6e](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/st.html) / evidence ritchie-5cfbec4274be6e-7cba78c0a380; [ritchie-5cfbec4274be6e](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/st.html) / evidence ritchie-5cfbec4274be6e-24812916f8e7)

- **documented**: Ritchie's adjustable-array proposal stored runtime bounds in pointers, rather than introducing variable-sized declared objects. It required extra pointer storage and restrictions ensuring bounds could be supplied; it was intended not to change existing conforming programs. - **documented**: Ritchie and Presotto described a separate privileged connection-setup program that centralizes negotiation and authentication, then returns a descriptor and exits so data does not pass through an extra process. ([ritchie-9b6fbbfa95a411](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/ipcpaper.html) / evidence ritchie-9b6fbbfa95a411-f3692e3d7a24; [ritchie-9b6fbbfa95a411](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/ipcpaper.html) / evidence ritchie-9b6fbbfa95a411-205467ebbea0)

- **documented**: Ritchie and Pike described resources as files in a hierarchical namespace accessed through Styx, enabling the same interface locally and remotely. Their model still depends on authentication and suitable transport. ([ritchie-032d8ab9a984c0](https://inferno-os.org/inferno/papers/styx.html) / evidence ritchie-032d8ab9a984c0-6022d3c10326; [ritchie-032d8ab9a984c0](https://inferno-os.org/inferno/papers/styx.html) / evidence ritchie-032d8ab9a984c0-523ae9f6ea40; [ritchie-032d8ab9a984c0](https://inferno-os.org/inferno/papers/styx.html) / evidence ritchie-032d8ab9a984c0-d098bc84d03f)

Limbo uses checked types and restricted pointers; its synchronous channels support both communication and synchronization.
