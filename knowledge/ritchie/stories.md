# Dennis M. Ritchie: stories

Built from 31 accepted distinct works and 138,939 source words. Compiled reasoning with source support and limits below.

- **documented**: From B to C and the Unix rewrite. Ritchie recounts that B's threaded code was too slow for the operating system, while its word-oriented model fit the byte-addressed PDP-11 poorly. In 1971 he added a character type and rewrote the compiler to emit machine instructions. Thompson's first rewrite attempt lacked structures; Ritchie later credited their addition with making kernel tables manageable for the 1973 rewrite. The lesson is to connect language features to an actual representation problem and implementation target. The work was collaborative, and the evidence does not assign the entire rewrite to Ritchie. - **documented**: Array conversion made structures practical. Ritchie found that B-style stored array-base pointers had no satisfactory place or initialization method inside structures, including structures describing directory data. His solution generated a pointer when the array name appeared in an expression rather than storing that pointer with the array. Most existing B code survived; programs that reassigned an array name needed repair. The case shows compatibility and representation being solved together, but its historical explanation is not a complete statement of every modern C array-conversion rule. ([ritchie-91fa14fdc827e6](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/chist.html) / evidence ritchie-91fa14fdc827e6-5c5b9dd1158f; [ritchie-50a70b87adf27f](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/cman.pdf) / evidence ritchie-50a70b87adf27f-4bea9c72626f; 2 independent supporting works)

- **documented**: Logical operators separated from bit operations. Ritchie reports that B treated the same operators as sequential tests in truth-value contexts and as bit operations elsewhere. The distinction was difficult to explain; at Alan Snyder's suggestion Ritchie introduced separate logical operators. Preserving precedence to ease conversion from B had an unfortunate consequence for masked-value tests. The useful lesson is that making semantics explicit can resolve a real usability problem, while compatibility choices can preserve a different source of error. ([ritchie-33d5c334116698](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/bcpl.html) / evidence ritchie-33d5c334116698-744887b35c39; [ritchie-91fa14fdc827e6](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/chist.html) / evidence ritchie-91fa14fdc827e6-9ed25ca58e0a; 2 independent supporting works)

- **documented**: The Interdata port exposed a hidden compiler dependency. Ritchie reports that a process-switching mechanism worked with the PDP-11 compiler's consistent return code but failed when Interdata return code varied with saved registers. After roughly a week, he and Steve Johnson abandoned attempts to adjust the compiler and redid the coroutine control-passing primitives. The case illustrates why machine-dependent boundaries must include calling conventions and compiler behavior, not merely instructions explicitly marked as assembly. It does not establish that every port requires the same repair. ([ritchie-c3458b73539dc9](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/odd.html) / evidence ritchie-c3458b73539dc9-bc85a8489992; [ritchie-be88b7b72521cb](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/portpap.html) / evidence ritchie-be88b7b72521cb-ca6d166a6742; 2 independent supporting works)

- **documented**: The broader Unix portability experiment. Johnson and Ritchie's proposal combined language changes, a retargetable compiler and an operating-system port; those were goals, not completed results at the proposal stage. Their 1978 report credits Thompson with the described kernel portability work, including corrected declarations and parameterized constants, and reports about 350 differing lines out of 7,000 in the operating-system proper. Johnson was credited with undertaking the portable compiler. The case supports isolating dependencies and checking assumptions, not attributing all the implementation work to Ritchie. ([ritchie-8aefaea5632426](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/firstport.html) / evidence ritchie-8aefaea5632426-75a46655fb39; [ritchie-be88b7b72521cb](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/portpap.html) / evidence ritchie-be88b7b72521cb-5627628b41e7; [ritchie-be88b7b72521cb](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/portpap.html) / evidence ritchie-be88b7b72521cb-49fa309c938f; 2 independent supporting works)

- **documented**: Recursive shells revealed a shared-offset bug. Ritchie describes commands started by a recursive shell inheriting an output offset that remained local to each process. A later command could overwrite the earlier command's output. The repair introduced a system table for open-file I/O pointers independent of the processes that opened them. The lesson is to test what sharing a handle means across process creation: copying a descriptor is not sufficient if the intended shared state remains process-local. This is his historical account, not a complete modern descriptor specification. ([ritchie-7ca8eec9ac8af9](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/hist.html) / evidence ritchie-7ca8eec9ac8af9-be7497928907; [ritchie-4495b38593615b](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/cacm.html) / evidence ritchie-4495b38593615b-91d6f752aec0; 2 independent supporting works)

- **documented**: Pipes changed the shape of utilities. Ritchie credits McIlroy's persistent advocacy and identifies a 1964 McIlroy proposal as background, while noting that related ideas predated Unix. In the later spelling-checker example, existing translation, sorting and comparison programs were combined with a dictionary and derivative generator. Ritchie's distinctive lesson is reuse of ordinary commands through a common interface, not that he invented all components or that linear pipelines solve every communication topology. ([ritchie-1bd73c8b9f492d](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/mdmpipe.html) / evidence ritchie-1bd73c8b9f492d-0caad08c1037; [ritchie-7ca8eec9ac8af9](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/hist.html) / evidence ritchie-7ca8eec9ac8af9-d728fd6527c4; [ritchie-504320fb4a7e46](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/retro.html) / evidence ritchie-504320fb4a7e46-ac37ba2fc657; 3 independent supporting works)

- **documented**: A misplaced compatibility bet on IBM/370. Johnson and Ritchie chose a calling convention compatible with a local BLISS implementation so they could use its I/O library. In retrospect they judged this unwise: the library did not help in other IBM environments, and some conventions made standard operating-system calls difficult. Their conclusion still allowed compatibility to justify call overhead in other circumstances. Evaluate the portability of the dependency and the interfaces it obstructs, not only the initial integration saving. ([ritchie-5d25d1308143eb](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/clcs.html) / evidence ritchie-5d25d1308143eb-592a18f2cf69; 1 independent supporting works)

- **documented**: Register arguments: a corrected assessment. In their September 1981 calling-sequence report, Johnson and Ritchie considered passing initial arguments in registers tempting but not yet practical under the architectures they had considered. A 2003 note says it did become practical shortly afterward; the supplied source does not identify the note's individual author. The case is useful because it preserves both judgments: an implementation constraint can be real at one moment without becoming a permanent architectural law. ([ritchie-5d25d1308143eb](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/clcs.html) / evidence ritchie-5d25d1308143eb-95a920ae4d68; 1 independent supporting works)

- **documented**: Unicos guest testing. Ritchie and David Slowinski worked on a guest facility so developers could test system changes without disrupting production users. The team chose a less efficient user-mode simulator because it was easier to develop and debug and required few kernel changes. The design had to validate relocated guest memory bounds and avoid raw writes to a partition simultaneously mounted by the host. It remained a development tool, not a general production virtual machine, and lacked the installation's networking support. - **documented**: Stream I/O replaced accumulating patches. Ritchie described the old character-I/O system as constrained by a single active line discipline and costly per-character queues; bypasses improved speed at the expense of regularity and modularity. His 1984 stream design used neighboring message-passing modules and block references, but he reported unresolved costs: reply timeouts, anonymous server accounting and no general multiplexing design yet. The case is not a clean victory narrative: a more regular architecture solved some problems while exposing others. ([ritchie-5cfbec4274be6e](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/st.html) / evidence ritchie-5cfbec4274be6e-6a82f9b9fc75; [ritchie-5cfbec4274be6e](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/st.html) / evidence ritchie-5cfbec4274be6e-7cba78c0a380; [ritchie-5cfbec4274be6e](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/st.html) / evidence ritchie-5cfbec4274be6e-63e42585cbac; [ritchie-5cfbec4274be6e](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/st.html) / evidence ritchie-5cfbec4274be6e-a1ac6d4c436e; 1 independent supporting works)

- **documented**: Standard I/O across unlike operating systems. Ritchie recalled that the original pre-ANSI interface took several attempts because PDP-11 Unix, Honeywell and IBM systems did not offer the same low-level operations. His separately authored appendix states goals of time and space efficiency, simple use and an interface applicable across machines even when implementation code is not portable. The operational lesson is to design against multiple real hosts. The evidence does not establish that Ritchie alone developed the entire library. - **documented**: Implementing Reeds's M-209 attack. Ritchie wrote a program implementing James Reeds's attack after Robert Morris showed him the work. He distinguished Reeds's statistical recovery of wheel pins from a more combinatorial lug-recovery stage that also owed ideas and code to Morris and Reeds. He reported readable decryption for about half of the tested English texts longer than 2,000 characters and most above 2,500, under stated prior assumptions and without guessed plaintext. Those results belong to that constrained experiment, not arbitrary ciphertexts. - **documented**: Unix time postponed an overflow. Ritchie recounts an early 32-bit representation counting sixtieths of a second from 1971, followed by epoch changes and a 1973 move to seconds from 1970. The latter extended the horizon but did not eliminate the eventual 2038 issue. The case teaches that changing units and origin can buy time without removing a finite-range limit. The cited page is his retrospective commentary on the first-edition manual, not the manual text itself.
