# Casey Muratori: positions

Built from 87 accepted distinct works and 1,166,408 source words. Compiled reasoning with source support and limits below.

- **documented**: Performance is resource use in service of the job, not just CPU speed. Measure the resource that affects the product: elapsed time, CPU, battery, network traffic or storage. A slow path may be commercially irrelevant, and a particular system may have concentrated hotspots, but neither conclusion should be assumed before investigation. His 2023 discussion rejects blanket excuses rather than asserting that every optimization pays for itself. ([casey-0610f7f8e7370b](https://www.computerenhance.com/p/performance-excuses-debunked) / evidence casey-0610f7f8e7370b-f5010a3daf09; [casey-0610f7f8e7370b](https://www.computerenhance.com/p/performance-excuses-debunked) / evidence casey-0610f7f8e7370b-2a2eda75d276; 1 independent supporting works)

- **inferred**: Performance awareness precedes optimization. Understand the likely costs of architecture and retain a credible route to the required budget; postpone intricate tuning when a local implementation can later be replaced. A quickly shipped slow first version can be reasonable, but it needs a real replacement plan and people capable of executing it. Do not mistake a current external bottleneck for permission to make every surrounding component equally slow. ([casey-0610f7f8e7370b](https://www.computerenhance.com/p/performance-excuses-debunked) / evidence casey-0610f7f8e7370b-f5261d8a0d46; [casey-ec87fbe5d368bb](https://www.youtube.com/watch?v=ffDXc6oup3Q&t=843) / evidence casey-ec87fbe5d368bb-5e0ddc7e2d55; [casey-c4bcf737873479](https://www.youtube.com/watch?v=czr1L3JocOI&t=660) / evidence casey-c4bcf737873479-41193302cd44; 3 independent supporting works)

- **inferred**: A hardware-based estimate is a diagnostic reference, not a promise of peak performance. Count the necessary work, estimate instruction throughput and data movement, then compare the order of magnitude with measurements. A gap between milliseconds of plausible work and seconds of execution deserves investigation; close-to-peak tuning may not. In one 2025 discussion he suggested that roughly within twice a practical estimate might be acceptable, explicitly as a ballpark rather than a universal threshold. ([casey-4231bba6844632](https://www.youtube.com/watch?v=Ge3aKEmZcqY&t=4950) / evidence casey-4231bba6844632-1b9a430135a2; [casey-4231bba6844632](https://www.youtube.com/watch?v=Ge3aKEmZcqY&t=4992) / evidence casey-4231bba6844632-55ea8d0d01dd; [casey-6b19e33ca50ad1](https://www.youtube.com/watch?v=apREl0KmTdQ&t=927) / evidence casey-6b19e33ca50ad1-7c9db8460d93; 2 independent supporting works)

- **inferred**: Read generated assembly when a consequential cost is unclear; do not infer machine work from the apparent simplicity of source. He teaches assembly literacy and a basic model of execution and caches, not routine handwritten assembly. For small noncritical expressions, retain the clear version rather than speculating about instruction choice. Compiler target, inlining and architecture matter, so inspect and time the actual build before claiming an improvement. ([casey-e6cd8d5c575533](https://www.computerenhance.com/p/performance-aware-programming-series) / evidence casey-e6cd8d5c575533-b9f538b1ed96; [casey-c7cc4ffcc8320c](https://www.youtube.com/watch?v=J3y1x54vyIQ&t=4042) / evidence casey-c7cc4ffcc8320c-0a933330d489; [casey-2414b2a6af2789](https://www.youtube.com/watch?v=nBBTPRO8AMI&t=731) / evidence casey-2414b2a6af2789-f053a1c05c09; 3 independent supporting works)

- **documented**: Microbenchmarks can expose a specific processor mechanism but are weak evidence for a broad language ranking. For comparisons, use multiple representative workloads, competent implementations and equivalent semantics; inspect startup, random-number generation and other work included in the timing. A tiny loop that suppresses optimizations can be useful for studying that suppression, but it does not establish how ordinary application code will behave. ([casey-4df96f5401e403](https://www.youtube.com/watch?v=RrHGX1wwSYM&t=310) / evidence casey-4df96f5401e403-bff0afba12a0; [casey-4df96f5401e403](https://www.youtube.com/watch?v=RrHGX1wwSYM&t=4631) / evidence casey-4df96f5401e403-26439ab5b356; [casey-4df96f5401e403](https://www.youtube.com/watch?v=RrHGX1wwSYM&t=2191) / evidence casey-4df96f5401e403-fceea2878395; 1 independent supporting works)

- **inferred**: Avoid confusing timestamp-counter ticks, core cycles and elapsed time. In 2014 he recommended QueryPerformanceCounter for the Windows game clock and RDTSC for profiling rather than synchronization. In the 2024 missing-increment investigation he further distinguishes invariant timestamp ticks from boosted core cycles and corroborates the surprising result with hardware counters. Neither a timer reading nor his proposed internal CPU mechanism alone proves what the processor did. ([casey-3a5f9b6fd06ffd](https://www.youtube.com/watch?v=TPpn2fee77M&t=2650) / evidence casey-3a5f9b6fd06ffd-ae6a39273439; [casey-2d44d2b966d482](https://www.computerenhance.com/p/the-case-of-the-missing-increment) / evidence casey-2d44d2b966d482-ecfe13811af8; [casey-2d44d2b966d482](https://www.computerenhance.com/p/the-case-of-the-missing-increment) / evidence casey-2d44d2b966d482-600d69597d63; 2 independent supporting works)

- **inferred**: For bulk work, organize data and computation around the operations actually performed. Look for repeated gathers, fixed query geometry, opportunities to precompute and values used together. Specialization can eliminate work that a general facility must do, but it incurs implementation and maintenance costs. Reuse is not inherently wrong: inspect whether the reused path meets the workload rather than assuming either that reuse is free or that rewriting is necessary. ([casey-4231bba6844632](https://www.youtube.com/watch?v=Ge3aKEmZcqY&t=6212) / evidence casey-4231bba6844632-e951dfd8aaaa; [casey-4231bba6844632](https://www.youtube.com/watch?v=Ge3aKEmZcqY&t=6296) / evidence casey-4231bba6844632-9c8e8301ea99; [casey-4231bba6844632](https://www.youtube.com/watch?v=Ge3aKEmZcqY&t=8826) / evidence casey-4231bba6844632-d5778d3a6a76; 1 independent supporting works)

- **inferred**: The performance cost of virtual dispatch can be the optimization it prevents, not merely an indirect call. Unknown implementations and separate compilation can obstruct inlining, combining related operations and vectorization. Small functions are not themselves the problem when the compiler can see and merge them; whole-program visibility and devirtualization can change the result. His 2023 shape benchmark also changed data layout, so its speedups cannot be attributed to dispatch alone. ([casey-d9000e3e01c172](https://www.computerenhance.com/p/clean-code-horrible-performance?embedding_publication_id=458709) / evidence casey-d9000e3e01c172-640b28d8c537; [casey-ec87fbe5d368bb](https://www.youtube.com/watch?v=ffDXc6oup3Q&t=205) / evidence casey-ec87fbe5d368bb-437540d56c50; [casey-2b14191bb0d252](https://www.youtube.com/watch?v=y8N5aP4EGBI&t=4992) / evidence casey-2b14191bb0d252-91d049430858; 3 independent supporting works)

- **inferred**: Do not make a domain-shaped inheritance tree the default implementation architecture. Cross-cutting operations may need direct access to properties spread across many kinds of entity; system-owned property collections with entity IDs are one alternative. His 2025 historical argument targets a particular hierarchy-centered pedagogy, not every definition of object-oriented programming. He allows that OOP can express the alternative and does not claim an entity-component system is universally best or that he personally uses one. ([casey-3608aac51c8dc6](https://www.youtube.com/watch?v=wo84LFzx5nI&t=661) / evidence casey-3608aac51c8dc6-6e86a28f5def; [casey-3608aac51c8dc6](https://www.youtube.com/watch?v=wo84LFzx5nI&t=5312) / evidence casey-3608aac51c8dc6-e37b2aefd857; [casey-2ae5f42d2138cd](https://www.youtube.com/watch?v=jHLbL1Eg4gM&t=2844) / evidence casey-2ae5f42d2138cd-46de20cf8b4d; 2 independent supporting works)

- **documented**: Choose representation from the kinds of variation and operations, not from a favored paradigm. For mutually exclusive alternatives, he favors a discriminated union and type-aware branches; for independently combinable features, a larger structure with flags can be appropriate. Consider whether new actions or new types are added more often. Overlapping storage saves memory but can make valid combinations impossible and create errors when the wrong interpretation is used. ([casey-3608aac51c8dc6](https://www.youtube.com/watch?v=wo84LFzx5nI&t=7305) / evidence casey-3608aac51c8dc6-46267e3d288f; [casey-3608aac51c8dc6](https://www.youtube.com/watch?v=wo84LFzx5nI&t=7361) / evidence casey-3608aac51c8dc6-f0a30efeef3b; [casey-3608aac51c8dc6](https://www.youtube.com/watch?v=wo84LFzx5nI&t=7508) / evidence casey-3608aac51c8dc6-8c09a5cf701e; 1 independent supporting works)

- **inferred**: Design an API from a realistic call site and tested implementation, not solely from a diagram of imagined objects. Write desired use, discover the information and operations it requires, then revise against real clients. For reusable libraries, multiple varied clients improve the evidence behind the abstraction. A design document can still come before production work when it records experiments rather than presenting untested speculation as established design. - **inferred**: Exposure versus encapsulation is a contract decision. Promise stable, useful representations when clients benefit from direct access; keep genuinely unsettled details internal, or provide an escape hatch whose maintenance risk is explicit. Granny 2 also accepted customer-selected vertex formats where one representation could not serve everyone. This does not mean exposing every incidental detail: a commercial library must solve users' integration problems without requiring them to become experts in its internals. ([casey-cd380aa86f0855](https://www.youtube.com/watch?v=0WYgKc00J8s&t=2286) / evidence casey-cd380aa86f0855-154333ad4f09; [casey-cd380aa86f0855](https://www.youtube.com/watch?v=0WYgKc00J8s&t=2201) / evidence casey-cd380aa86f0855-b1af0d160311; [casey-ec87fbe5d368bb](https://www.youtube.com/watch?v=ffDXc6oup3Q&t=1092) / evidence casey-ec87fbe5d368bb-5dae8c0982b1; 2 independent supporting works)

- **inferred**: Compress after exploration, not before requirements are understood. Start with concrete working code, extract repeated operations and condense representations once their use is visible. Keep an abstraction only if it earns its cost in correctness, developer time, performance or actual flexibility. Conversely, do not remove an apparently redundant structure until its distinct capability is understood; independent debug views, for example, require independent view state. - **inferred**: Trivial getters and setters are not mandatory insurance against change. In the 2016 layout discussion he would add one when changing the field has behavior, or when that behavior is highly likely, rather than automatically wrapping every field. His approximate 90 percent condition was a personal judgment, not a measured threshold. Typed allocation helpers or checked conversions, by contrast, can earn an interface by preventing a concrete class of mistake. ([casey-0bb7c24537b7a4](https://www.youtube.com/watch?v=BHEJh9Yvsxc&t=2758) / evidence casey-0bb7c24537b7a4-7022f7e51974; [casey-0e18cb5a9963dc](https://www.youtube.com/watch?v=kXQMyg4Prfo&t=341) / evidence casey-0e18cb5a9963dc-aa1a53af0535; [casey-4dbdb3d822fbe3](https://www.youtube.com/watch?v=kdAte9pdLv8&t=2249) / evidence casey-4dbdb3d822fbe3-ffe8500e4218; 3 independent supporting works)

- **documented**: Immediate-mode UI can keep application data with the application and express controls and their actions in the ordinary update path. A shared context still needs interaction state, stable identities and, for controls such as text editing, additional temporary state. The trade-offs include harder selective redraw and potentially one-frame layout lag unless extra passes are introduced. His 2005 presentation describes one implementation, not a state-free definition of every immediate-mode UI. - **inferred**: A game-platform boundary should expose the limited services each side actually needs while leaving each platform free to organize its own control flow. Put portable game behavior above that boundary and platform-specific input, I/O and orchestration below it. The clean single-call picture is not literal: asynchronous disk and networking can require queues or callbacks. He presents a virtual operating-system interface as a viable alternative, not a forbidden design. - **inferred**: Hot reload and replay are iteration tools, not free migration of arbitrary state. Keep durable game memory outside the reloadable library, restore the recorded starting state and feed recorded inputs back into updates. A fixed memory base can preserve pointers within a raw snapshot, but changed structure layouts, stale function or vtable pointers, external state and thread scheduling complicate correctness. Restarting occasionally can be cheaper than building a general migration system. - **inferred**: Choose memory policy for the workload's reliability requirements. For a constrained game he favors a large startup allocation partitioned into bounded subsystem storage, making footprint and failure assumptions visible. Dynamic allocation remains reasonable where hard bounds are unnecessary. Virtual allocation does not prove physical RAM is available, and reloadable modules must agree on allocation ownership; allocation in one runtime heap and freeing in another can fail. - **inferred**: Profile at two scales: keep an inexpensive overview of frame costs and spikes, then add detailed instrumentation to the suspicious region. Preserve thread overlap and historical events when those answer the question, but account for instrumentation cost and storage pressure. The profiler itself can become the bottleneck or alter the bug. A completed stutter is already in the past, so stopping afterward is not equivalent to recovering the state that caused it. - **inferred**: Use assertions for violated invariants, not ordinary conditions that the program must handle. A size narrowing or array bound can be asserted in a controlled debug path; a missed frame or unavailable asset needs a handling or reporting strategy. - **inferred**: Unit tests and TDD are tools, not universal development drivers. He used regression tests for core library routines and recognizes that unit tests find bugs. He is more skeptical of making them the primary method for games whose difficult failures arise through long sequences, user input and interactions across systems. Select tests by expected bugs prevented, maintenance cost and change friction; complement them with instrumentation, replay and playtesting. - **inferred**: Game timing is a budget and synchronization problem, not a single FPS number.
