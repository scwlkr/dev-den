# Bjarne Stroustrup: stories

Built from 81 accepted distinct works and 720,818 source words. Compiled reasoning with source support and limits below.

- **documented**: Simula and BCPL simulator. As a researcher, Stroustrup built a distributed-system simulator that benefited from Simula's organization and checking but was impractical to run on the available machine. A BCPL rewrite restored usable performance while making implementation and debugging more painful. The operational lesson was to seek both abstraction and affordable execution, and to distinguish a language's ideas from the costs of a particular implementation. His later speedup estimate is a recollection, not a general comparison of the languages. - **documented**: Cfront as a portability strategy. Stroustrup used C as a compiler target rather than building a separate backend for every machine. Cfront performed C++ syntax and semantic analysis and generated C for existing compiler and tool infrastructure; a target probe supplied machine properties. This made deployment practical but added compilation work. The lesson is to reuse a mature boundary when it meets the need, without confusing the generated representation with the source language. ([bjarne-faf11ea2080fa8](https://www.stroustrup.com/hopl2.pdf) / evidence bjarne-faf11ea2080fa8-85b8157c5e71; [bjarne-189b97e60bf82d](https://www.youtube.com/watch?v=ZO0PXYMVGSU&t=3039) / evidence bjarne-189b97e60bf82d-530c34422eb3; 2 independent supporting works)

- **documented**: Macros for generic containers. He recognized early that containers needed type parameters, but initially expected macros to do the job. Experience showed that the approach did not scale beyond small collaborations. Templates addressed the underlying need more systematically, though their initial interfaces and diagnostics remained weak. Preserve the distinction between identifying the right problem and having the right solution; a failed mechanism is not evidence that the problem was imaginary. ([bjarne-189b97e60bf82d](https://www.youtube.com/watch?v=ZO0PXYMVGSU&t=3384) / evidence bjarne-189b97e60bf82d-33da6c40efd8; [bjarne-15c9eb40135f1c](https://www.youtube.com/watch?v=nQPumFkN-Ow&t=1263) / evidence bjarne-15c9eb40135f1c-f2ceb64b4d6c; [bjarne-bfe3fa970f3ba6](https://stroustrup.com/Programmez239English.pdf) / evidence bjarne-bfe3fa970f3ba6-da199c95bbdf; 3 independent supporting works)

- **documented**: The missing early library. Stroustrup later called the lack of a sufficiently useful basic library in the first release a serious mistake: users independently built incompatible fundamental facilities. He lacked templates and a satisfactory general container design, and delivery was constrained by time and exhaustion. Later he said he should have delayed for template-like support, while also acknowledging that a delay could have stalled the language and might not have produced a solution. ([bjarne-faf11ea2080fa8](https://www.stroustrup.com/hopl2.pdf) / evidence bjarne-faf11ea2080fa8-137a1e374c97; [bjarne-2ac5f49ea2025b](https://www.youtube.com/watch?v=U46fJ2bJ-co&t=6732) / evidence bjarne-2ac5f49ea2025b-bd4044610566; [bjarne-d1ed959b783a46](https://www.youtube.com/watch?v=iCw_Wg835bg&t=3826) / evidence bjarne-d1ed959b783a46-7e2b520537e5; 3 independent supporting works)

- **documented**: Reconsidering the STL. Stroustrup initially found Alexander Stepanov's library unfamiliar and unattractive. He compared it with his established container criteria and changed his mind when it met nearly all of them, including efficiency and generality. He credits Stepanov, Meng Lee and David Musser, and describes his own technical contributions as minor. The lesson is to test an unfamiliar design against explicit requirements rather than preserve an initial aesthetic judgment. ([bjarne-032faa90b6e56c](https://www.stroustrup.com/hopl-almost-final.pdf) / evidence bjarne-032faa90b6e56c-45cb0c478a45; [bjarne-032faa90b6e56c](https://www.stroustrup.com/hopl-almost-final.pdf) / evidence bjarne-032faa90b6e56c-a1e2b9ba6494; [bjarne-5877b33c3b0e61](https://www.stroustrup.com/DnE2005.pdf) / evidence bjarne-5877b33c3b0e61-3a5abf1cb492; 2 independent supporting works)

- **documented**: Reducing the STL proposal. To make standardization manageable, Stroustrup and library experts removed roughly two-thirds of the original proposed text, asking whether each retained facility was necessary and broadly beneficial. Even the reduced library delayed the standard by more than a year. This is a case of limiting scope to available review, implementation and teaching capacity, not a claim that omitted facilities lacked value. ([bjarne-032faa90b6e56c](https://www.stroustrup.com/hopl-almost-final.pdf) / evidence bjarne-032faa90b6e56c-31d236fa47a6; [bjarne-5877b33c3b0e61](https://www.stroustrup.com/DnE2005.pdf) / evidence bjarne-5877b33c3b0e61-6da137640f9f; 2 independent supporting works)

- **documented**: RTTI after an initial omission. Stroustrup initially left out runtime type identification because he had seen type tests used as inefficient and unmaintainable switches. Later, incompatible library-specific mechanisms and the need to recover application-derived objects through library interfaces motivated a standard facility. He coauthored the proposal with Dmitry Lenkov. The correction was not an endorsement of pervasive type switching: use runtime identification for genuine interface-boundary needs. ([bjarne-032faa90b6e56c](https://www.stroustrup.com/hopl-almost-final.pdf) / evidence bjarne-032faa90b6e56c-f4ad2ad17b2c; [bjarne-faf11ea2080fa8](https://www.stroustrup.com/hopl2.pdf) / evidence bjarne-faf11ea2080fa8-9fcd98628dc6; 2 independent supporting works)

- **documented**: Template export compromise. Stroustrup favored separate compilation to protect implementation boundaries and reduce header-context interference; opponents warned that implementation would be difficult. He later judged both sides substantially right: the compromise worked but imposed complexity, had ABI consequences and delivered only some anticipated benefits. He credits EDG implementers Steve Adamczyk, John Spicer and David Vandevoorde. The case warns against treating either design cleanliness or implementability as sufficient on its own. ([bjarne-032faa90b6e56c](https://www.stroustrup.com/hopl-almost-final.pdf) / evidence bjarne-032faa90b6e56c-e57ee77ce1a9; [bjarne-5877b33c3b0e61](https://www.stroustrup.com/DnE2005.pdf) / evidence bjarne-5877b33c3b0e61-442818eff290; 2 independent supporting works)

- **documented**: A failed garbage-collection assumption. In a 1995 proposal, Stroustrup believed conservative garbage collection was already compatible with the draft. He later recognized a counterexample: a pointer could be written to a file and restored after the collector considered its storage unreachable. He also criticized his own failure to define optional collection precisely. The practical lesson is to check a proposed runtime model against the actual language contract and specify its boundary conditions. ([bjarne-032faa90b6e56c](https://www.stroustrup.com/hopl-almost-final.pdf) / evidence bjarne-032faa90b6e56c-85bf736deef0; 1 independent supporting works)

- **documented**: Vector assignment and exception safety. In an illustrative implementation, deleting old storage before allocating a replacement can leave the object with a dangling representation if allocation fails, leading to another deletion during unwinding. Stroustrup's remedy constructs a replacement before discarding the old state. Copy-and-swap can provide a strong guarantee, while reusing capacity may be faster but permit partial change. The choice depends on element operations and the guarantee clients actually need. ([bjarne-783c826311cb99](https://www.stroustrup.com/eh_brief.pdf) / evidence bjarne-783c826311cb99-23b883eaa981; [bjarne-783c826311cb99](https://www.stroustrup.com/eh_brief.pdf) / evidence bjarne-783c826311cb99-8822140cacd0; [bjarne-94f225ac3002e4](https://www.stroustrup.com/except.pdf) / evidence bjarne-94f225ac3002e4-6dc006a520bc; 2 independent supporting works)

- **documented**: Iterator requirements and single-pass input. In work with Andrew Sutton, the authors examined a vector range constructor that might traverse input twice to optimize allocation. That is valid only for an appropriately multi-pass source; selecting it for a single-pass stream is a semantic error and may wait for additional input. The case shows why an interface needs semantic and complexity requirements, not merely a list of expressions that compile. ([bjarne-72241b845beaaf](https://www.stroustrup.com/sle2011-concepts.pdf) / evidence bjarne-72241b845beaaf-df4a06e4c837; [bjarne-72241b845beaaf](https://www.stroustrup.com/sle2011-concepts.pdf) / evidence bjarne-72241b845beaaf-99970709ea40; 1 independent supporting works)

- **documented**: Vector versus list measurement. In John Bentley's insertion-and-removal exercise, Stroustrup found that contiguous traversal could outweigh the apparent advantage of linked-list insertion and deletion. He also recalls an unexpected twofold improvement from replacing a tiny list with a vector. The lesson is to measure the whole workload, including cache and traversal; larger elements and different operations can reverse the outcome, so neither example bans lists. ([bjarne-6d78140a0c291c](https://www.stroustrup.com/bs_faq.html) / evidence bjarne-6d78140a0c291c-a43fe08fba8b; [bjarne-c9839d4ff3a827](https://isocpp.org/blog/2014/06/stroustrup-lists) / evidence bjarne-c9839d4ff3a827-5a831cdd4316; [bjarne-c9839d4ff3a827](https://isocpp.org/blog/2014/06/stroustrup-lists) / evidence bjarne-c9839d4ff3a827-a5da1e6ae3f9; 1 independent supporting works)

- **documented**: Fluid simulation refactoring. J. Daniel Garcia and Stroustrup refactored fluidanimate to express its existing algorithms more directly, introducing domain abstractions and sharing more code across sequential and TBB modes. Their reported single code base was smaller and executed about 20% fewer instructions, while some L1 accesses and misses increased. The study supports measuring maintainability and machine behavior together; it does not establish a universal speedup or imply every locality metric improved. ([bjarne-7db324a86881a5](https://www.stroustrup.com/improving_garcia_stroustrup_2015.pdf) / evidence bjarne-7db324a86881a5-8a4047a3cc92; [bjarne-7db324a86881a5](https://www.stroustrup.com/improving_garcia_stroustrup_2015.pdf) / evidence bjarne-7db324a86881a5-92f26a939ddc; [bjarne-7db324a86881a5](https://www.stroustrup.com/improving_garcia_stroustrup_2015.pdf) / evidence bjarne-7db324a86881a5-d6646d6f7eff; 1 independent supporting works)

- **documented**: Local analysis and the widget factory. A factory may return a widget that depends on a window but not on a local logger. Stroustrup's proposed local analyzer cannot generally establish that distinction, so it may reject a safe return. Moving the logger outside the function can make the lifetime clearer; a targeted assertion is another possibility, but may not always be verifiable. The case exposes the cost of scalable conservative analysis and the risk of treating suppression as proof.
