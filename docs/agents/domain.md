# Domain docs

## Layout

This is a single-context repository:

- `GLOSSARY.md` at the repository root defines domain vocabulary.
- `docs/adr/` contains architecture decision records.

## Consumer rules

Before exploring, read the glossary and ADRs relevant to your work.
If they do not exist, proceed silently. Do not create placeholders;
domain-modeling creates documentation as terms and decisions resolve.

Use glossary terms consistently in issues, proposals, code, and tests.
If a needed term is missing, reconsider the wording or note the gap
for domain-modeling.

Explicitly flag proposals that contradict an existing ADR and explain
why the decision should be reconsidered.
